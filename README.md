# tipa-faq

Локальный TypeScript-проект для формирования и обслуживания базы FAQ по строительным видео TIPA HOUSE. На вход подаются текстовые расшифровки видео, на выходе обновляется `data/faq.json` с вопросами, ответами автора, независимыми ответами ИИ, тематическими разделами, тегами и ссылками на исходные вопросы.

## Быстрый запуск

### Обычный рабочий цикл

После добавления или изменения файлов расшифровок в `transcripts/` выполни из корня проекта:

```bash
npm run process
npm run faq:finish
```

- `npm run process` извлекает Q&A из новых или изменённых расшифровок и объединяет их с базой.
- `npm run faq:finish` запускает последующую обработку и проверки: заполняет отсутствующие AI-ответы, пересчитывает сравнение ответов, проверяет FAQ и теги, проверяет наличие evidence и выводит статистику.

Команда `faq:finish` прекращает выполнение, если один из этапов завершился ошибкой. Исправь ошибку и запусти команду повторно.

### Первый запуск

```bash
npm install
npm run check
```

Перед обработкой проверь настройки Ollama и наличие обязательных входных файлов — см. разделы ниже.

## Требования и настройка ИИ

- Node.js и npm.
- Запущенный локальный Ollama с установленной моделью либо совместимый API, доступный по адресу, указанному в конфигурации.
- Файл `.env` в корне проекта при необходимости переопределить настройки по умолчанию.

`src/ai.ts` использует следующие переменные:

```env
OPENAI_MODEL=qwen3.5:2b
OLLAMA_URL=http://localhost:11434/api/chat
```

Это пример для локального Ollama, а не обязательный выбор модели. Значения по умолчанию в коде: `OPENAI_MODEL=qwen3.5:4b` и `OLLAMA_URL=http://localhost:11434/api/chat`. На компьютере с ограниченной памятью можно выбрать более лёгкую установленную модель, например `qwen3.5:2b`.

Проверь доступные модели:

```bash
ollama list
```

Проверь, что Ollama запущен и выбранная модель действительно доступна. Не добавляй в `.env` с реальными секретами в репозиторий.

## Входные данные

### `transcripts/`

Помести сюда исходные текстовые расшифровки с расширением `.txt`. В основной обработке текст делится на фрагменты, после чего модель извлекает Q&A. Для восстановления цитат `evidence` исходная расшифровка должна оставаться доступной под тем же именем файла.

### `prompts/extract-faq.md`

Основной процесс читает промпт извлечения из `prompts/extract-faq.md`. Убедись, что каталог `prompts/` и этот файл есть в рабочей копии проекта. Если их нет в архиве или локальной папке, скопируй их из своей рабочей версии проекта перед запуском `npm run process`.

### Файлы `data/`

- `data/faq.json` — основная база Q&A.
- `data/tags.json` — словарь тегов.
- `data/sections.json` — список тематических разделов.
- `data/processed.json` — реестр обработанных расшифровок и их хешей.

Если хеш файла в `processed.json` не изменился, `npm run process` пропустит расшифровку. Чтобы запустить повторную обработку, меняй исходный текст осознанно или корректируй реестр после резервного копирования.

## Ответ автора и независимое мнение ИИ

Каждая запись FAQ может содержать два самостоятельных ответа:

- `answer` — ответ автора, отредактированный для ясности, но основанный на исходном материале.
- `aiAnswer` — независимый ответ ИИ на тот же вопрос. Он хранится отдельно и не должен выдаваться за слова автора.
- `aiComparison` — сравнение двух ответов:
  - `status`: `agree`, `partially_agree`, `disagree` или `not_comparable`;
  - `agreementPercent`: ориентировочная оценка смыслового совпадения от 0 до 100;
  - `summary`: краткое пояснение совпадений или расхождений.

Процент — субъективная оценка модели, а не вероятность правильности ответа и не независимая проверка фактов. При расхождении ответов следует проверить исходную расшифровку и технические утверждения вручную.

### Связанные команды

```bash
npm run faq:ai-answers
npm run faq:ai-compare
```

`faq:ai-answers` создаёт независимые AI-ответы только для записей, у которых `aiAnswer` отсутствует или пустой; для таких записей также рассчитывается сравнение. Уже существующие непустые AI-ответы эта команда не перезаписывает.

`faq:ai-compare` пересчитывает сравнение для всех записей, в которых есть оба ответа. Сам текст `answer` и `aiAnswer` эта команда не генерирует заново.

При обычном `npm run process` новые извлечённые Q&A получают `aiAnswer` и `aiComparison`. При слиянии с базой уже имеющийся непустой AI-ответ не перезаписывается автоматически.

## Как работает `faq:finish`

Команда запускает этапы именно в следующем порядке:

1. `npm run faq:ai-answers` — добавляет отсутствующие независимые ответы ИИ.
2. `npm run faq:ai-compare` — пересчитывает сравнение, используя имеющиеся ответы.
3. `npm run faq:check` — проверяет структуру FAQ.
4. `npm run faq:check-tags` — проверяет теги.
5. `npm run faq:check-evidence` — показывает состояние подтверждающих цитат.
6. `npm run faq:stats` — выводит статистику.

Обрати внимание: `faq:finish` не восстанавливает отсутствующие `evidence` автоматически и не гарантирует фактическую достоверность ответов. Если проверка показывает записи без цитат, отдельно выполни `npm run faq:evidence`, а затем повтори `npm run faq:check-evidence`.

## Структура FAQ (`data/faq.json`)

Файл `data/faq.json` — основная база вопросов и ответов. На верхнем уровне хранится объект:

| Поле | Тип | Назначение |
|---|---|---|
| `version` | number | Версия формата базы |
| `updatedAt` | string \| null | Время последнего обновления базы в ISO-формате |
| `items` | array | Массив записей FAQ |

### Поля одной записи `items[]`

| Поле | Тип | Назначение |
|---|---|---|
| `id` | string | Уникальный идентификатор FAQ |
| `title` | string | Краткий заголовок |
| `question` | string | Текущая нормализованная формулировка вопроса |
| `answer` | string | Основной ответ для FAQ — ответ автора в текущей редакции; это не независимое мнение AI |
| `originalQuestion` | string, необязательно | Вопрос до редакторской правки |
| `originalAnswer` | string, необязательно | Ответ автора до редакторской правки |
| `editedQuestion` | string, необязательно | Отредактированная формулировка вопроса |
| `editedAnswer` | string, необязательно | Отредактированная версия ответа автора |
| `aiAnswer` | string, необязательно | **Независимый ответ AI. Именно здесь хранится текст стороннего мнения AI**, отдельно от `answer` и `editedAnswer` |
| `aiComparison` | object, необязательно | Сравнение `aiAnswer` с ответом автора; структура описана ниже |
| `evidence` | string, необязательно | Цитата из исходной расшифровки, подтверждающая ответ автора |
| `reviewStatus` | `pending` \| `review` \| `ready` | Статус редакторской проверки записи; это **не** статус совпадения AI с автором |
| `reviewReasons` | string[] | Причины, по которым требуется проверка |
| `comment` | string | Дополнительный комментарий |
| `relatedQuestions` | array | Исходные формулировки, объединённые в эту запись; элементы содержат `id`, `file`, `question` |
| `sections` | string[] | ID тематических разделов из `data/sections.json` |
| `tags` | string[] | Теги записи, сверяемые со словарём `data/tags.json` |
| `sources` | array | Исходные материалы; обычно элементы содержат `file` и могут содержать `title` |
| `updatedAt` | string | Время обновления конкретной записи в ISO-формате |

### `aiAnswer` и статус сравнения `aiComparison`

AI-ответ и результат его сравнения хранятся **внутри той же записи FAQ в `data/faq.json`**. Текст независимого мнения записывается в поле `aiAnswer`. Результат сравнения записывается отдельно в объект `aiComparison`:

| Поле | Тип | Значение |
|---|---|---|
| `aiComparison.status` | string | Категория смыслового отношения AI-ответа к ответу автора: `agree`, `partially_agree`, `disagree` или `not_comparable` |
| `aiComparison.agreementPercent` | number | Оценка смыслового совпадения от 0 до 100 по мнению модели; это не вероятность правильности ответа |
| `aiComparison.summary` | string | Краткое объяснение совпадений, частичных совпадений или расхождений |

Значения `aiComparison.status` означают:

- `agree` — ответы в основном совпадают по смыслу;
- `partially_agree` — есть общая часть, но также присутствуют существенные различия или дополнительные оговорки;
- `disagree` — ответы противоречат друг другу или дают разные выводы;
- `not_comparable` — сравнить ответы надёжно нельзя, например, если они отвечают на разные вопросы или недостаточно содержательны.

**Важно не путать два разных статуса:** `aiComparison.status` показывает отношение независимого AI-ответа к ответу автора, а `reviewStatus` показывает состояние редакторской проверки FAQ. Например, `aiComparison.status: "disagree"` само по себе не меняет `reviewStatus` автоматически и не означает, что AI прав. Расхождения нужно проверить по `evidence` и исходной расшифровке.

Пример фрагмента одной записи:

```json
{
  "id": "primer-voprosa",
  "question": "Нужно ли утеплять фундамент?",
  "answer": "Ответ автора из исходного материала.",
  "aiAnswer": "Независимое мнение AI по этому же вопросу.",
  "aiComparison": {
    "status": "partially_agree",
    "agreementPercent": 70,
    "summary": "Основной вывод совпадает, но AI добавляет условия, которых нет в ответе автора."
  },
  "reviewStatus": "review",
  "reviewReasons": ["Проверить различия между ответом автора и AI"]
}
```

Это иллюстративный пример структуры, а не техническая рекомендация по утеплению.

### `relatedQuestions`, `sections` и `tags`

`relatedQuestions` содержит исходные формулировки, связанные с итоговой записью. `sections` — широкие тематические разделы, заданные в `data/sections.json`; `tags` — более конкретные метки из словаря `data/tags.json`.

Некоторые поля могут отсутствовать у старых записей, поскольку база формировалась в несколько этапов. Отсутствие `aiAnswer` означает, что независимый ответ ещё не сохранён. Запусти `npm run faq:ai-answers` или общую команду `npm run faq:finish`, чтобы заполнить отсутствующие AI-ответы и рассчитать сравнение.

### Статусы редакторской проверки

| `reviewStatus` | Значение |
|---|---|
| `pending` | Запись ожидает проверки |
| `review` | Запись требует ручной проверки |
| `ready` | Запись прошла предусмотренную проверку |

`ready` не гарантирует фактическую достоверность. Технические утверждения и расхождения между `answer` и `aiAnswer` следует проверять по исходным материалам.

## Evidence — подтверждающая цитата

`evidence` — фрагмент исходной расшифровки, который подтверждает ответ. Рекомендуемый порядок восстановления:

```bash
npm run faq:backup
npm run faq:check-evidence
npm run faq:evidence
npm run faq:check-evidence
```

Восстановление использует сведения об источниках/связанных вопросах, подбирает релевантные фрагменты и просит модель выбрать цитату. Перед сохранением проверяется, что цитата содержится в полном тексте исходной расшифровки. Это подтверждает буквальное присутствие фрагмента, но не гарантирует, что он доказывает весь ответ: смысл цитаты нужно проверить вручную.

Если исходного файла больше нет в `transcripts/`, восстановить цитату этим способом не получится.

## Резервные копии

Перед массовыми изменениями можно запустить:

```bash
npm run faq:backup
```

Резервные копии создаются рядом с исходными JSON-файлами с суффиксом `.bak` (например, `data/faq.json.bak`). При некоторых операциях резервная копия создаётся автоматически. Не рассчитывай только на автоматическую копию: перед значительными изменениями полезно отдельно сохранить проект или сделать Git-коммит.

## Рекомендуемый рабочий процесс

Для повседневной работы:

```bash
# 1. Добавить/обновить .txt в transcripts/
npm run process

# 2. Заполнить AI-ответы, пересчитать сравнение и выполнить проверки
npm run faq:finish
```

Если менялся код:

```bash
npm run check
```

Если менялись правила классификации и нужно обновить теги существующей базы:

```bash
npm run faq:backup
npm run faq:retag
npm run faq:check-tags
```

Если требуется восстановить цитаты:

```bash
npm run faq:backup
npm run faq:evidence
npm run faq:check-evidence
```

## Важные принципы

- Не придумывать строительные факты, нормы, размеры и технические характеристики, которых нет в источнике.
- Не смешивать ответ автора и независимое мнение ИИ.
- Не считать процент совпадения доказательством истинности ответа.
- Не считать наличие `evidence` достаточным без смысловой проверки цитаты.
- Сохранять исходные расшифровки, чтобы можно было проверить ответы и восстановить цитаты.
- Перед массовыми изменениями сохранять резервную копию.
- При расхождениях между ответом автора и ИИ отдавать приоритет проверке первоисточника, а не автоматическому проценту.
