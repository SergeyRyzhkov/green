# tipa-faq

Инструмент для автоматического формирования строительной базы знаний из текстовых расшифровок видео.

Проект использует локальную LLM через Ollama, извлекает вопросы и ответы, редактирует формулировки, классифицирует записи по разделам и тегам, объединяет FAQ и проверяет качество данных.

## Возможности

* Извлечение FAQ из текстовых расшифровок.
* Разбиение больших текстов на фрагменты.
* Редактирование вопросов и ответов.
* Классификация по фиксированным разделам.
* Автоматическая генерация тематических тегов и пополнение словаря.
* Объединение похожих FAQ из разных источников.
* Сохранение исходных вопросов, ответов и подтверждающих цитат.
* Контроль качества и отметка записей, требующих ручной проверки.
* Отдельная утилита для диагностики и обслуживания JSON-файлов.

## Требования

* Node.js.
* npm.
* Ollama с установленной моделью.
* TypeScript и `tsx`, используемые проектом.

Настройки модели и подключения к Ollama хранятся в `.env`.

Пример настроек:

```env
OPENAI_MODEL=qwen3.5:4b
OLLAMA_URL=http://localhost:11434/api/chat
```

Используй фактические значения из своего `.env`. Не добавляй в README секреты и персональные ключи.

## Первый запуск

### 1. Установить зависимости

В корне проекта:

```bash
npm install
```

### 2. Запустить Ollama

Проверь, что Ollama запущена и модель доступна:

```bash
ollama list
```

Если нужной модели нет, установи её, например:

```bash
ollama pull qwen3.5:4b
```

### 3. Подготовить исходные данные

Положи текстовые расшифровки в каталог `transcripts/`.

Файлы должны иметь расширение `.txt`.

Убедись, что в `prompts/` находится `extract-faq.md`, а в `data/` — корректный `sections.json` с фиксированным перечнем разделов.

Если файлы `faq.json`, `tags.json` и `processed.json` отсутствуют, программа может использовать начальные значения при чтении. Для записи файлов функция `writeJson` создаёт каталог назначения автоматически.

### 4. Запустить обработку

```bash
npx tsx src/process.ts
```

Для каждого нового или изменённого файла программа извлекает FAQ, выполняет последующие этапы обработки, объединяет результаты с базой и сохраняет JSON.

### 5. Проверить результат

```bash
npm run faq:stats
npm run faq:check
npm run faq:check-tags
```

Перед дальнейшей обработкой изучи предупреждения валидатора.

## Последовательность обработки

### Этап 1. Извлечение

Текст расшифровки разбивается на фрагменты. Модель выделяет вопросы, ответы и доступные подтверждения из исходного текста.

### Этапы 2–3. Редактирование и классификация

Вопросы и ответы приводятся к удобной для базы форме. Записям назначаются разделы и другие классификационные данные.

### Этап 4. Объединение

Результаты сопоставляются с уже существующими FAQ. Похожие записи могут объединяться, а источники и тематические метки — дополняться.

### Этап 5. Проверка

Валидатор проверяет структуру, уникальность идентификаторов, разделы, теги, источники и признаки качества.

Предупреждение валидатора не всегда означает ошибку структуры: например, отсутствие цитаты — это проблема подтверждения ответа, а не обязательно некорректный JSON.

### Повторная обработка

Для уже существующих FAQ предусмотрена отдельная классификация тегов:

```bash
npm run faq:retag
```

Она не заменяет извлечение из исходных расшифровок.

## Обслуживание базы

Для повседневной работы используется `src/maintenance.ts`.

| Команда                      | Назначение                              |
| ---------------------------- | --------------------------------------- |
| `npm run maintenance`        | Справка по доступным командам           |
| `npm run faq:stats`          | Статистика базы                         |
| `npm run faq:check`          | Полная проверка FAQ                     |
| `npm run faq:check-tags`     | Проверка словаря тегов                  |
| `npm run faq:check-evidence` | Список FAQ без цитат                    |
| `npm run faq:retag`          | Повторная генерация тегов               |
| `npm run faq:clean-tags`     | Удаление тегов, дублирующих ID разделов |
| `npm run faq:backup`         | Резервные копии файлов данных           |

Команды доступны после добавления соответствующих записей в `scripts` файла `package.json`.

### Безопасный порядок работы

После извлечения FAQ:

```bash
npm run faq:stats
npm run faq:check
npm run faq:check-tags
```

Перед изменением данных:

```bash
npm run faq:backup
```

После изменения:

```bash
npm run faq:stats
npm run faq:check
npm run faq:check-tags
```

`faq:retag` повторно обращается к модели. `faq:clean-tags` изменяет назначения тегов и словарь. Перед такими операциями убедись, что актуальные данные сохранены.

## Структура данных

Все файлы в `data/` хранятся в формате JSON с отступами для удобства чтения.

### `faq.json` — база вопросов и ответов

Верхний уровень:

```json
{
  "version": 1,
  "updatedAt": "2026-10-09T00:00:00.000Z",
  "items": []
}
```

Поля:

| Поле        | Тип               | Значение                         |
| ----------- | ----------------- | -------------------------------- |
| `version`   | number            | Версия структуры файла           |
| `updatedAt` | string или `null` | Время последнего обновления базы |
| `items`     | array             | Массив FAQ                       |

Каждая запись FAQ имеет следующие поля:

| Поле               | Тип                   | Значение                                         |
| ------------------ | --------------------- | ------------------------------------------------ |
| `id`               | string                | Уникальный идентификатор записи                  |
| `title`            | string                | Краткий заголовок FAQ                            |
| `question`         | string                | Основной вопрос, используемый в базе             |
| `answer`           | string                | Основной ответ, используемый в базе              |
| `originalQuestion` | string, необязательно | Исходный вопрос до редактирования                |
| `originalAnswer`   | string, необязательно | Исходный ответ до редактирования                 |
| `editedQuestion`   | string, необязательно | Отредактированный вопрос                         |
| `editedAnswer`     | string, необязательно | Отредактированный ответ                          |
| `evidence`         | string, необязательно | Подтверждающая цитата из расшифровки             |
| `reviewStatus`     | string, необязательно | Статус проверки: `pending`, `review` или `ready` |
| `reviewReasons`    | array, необязательно  | Причины, по которым требуется проверка           |
| `comment`          | string                | Дополнительный комментарий                       |
| `sourceQuestions`  | array                 | Исходные вопросы, связанные с записью            |
| `sections`         | array                 | ID тематических разделов                         |
| `tags`             | array                 | Тематические теги                                |
| `sources`          | array                 | Источники, из которых получена информация        |
| `updatedAt`        | string                | Дата обновления записи                           |

#### `sourceQuestions`

Массив связей с исходными вопросами:

```json
[
  {
    "file": "09_26.txt",
    "question": "Исходная формулировка вопроса"
  }
]
```

`file` — имя исходного файла. `question` — исходная формулировка, если она сохранена.

#### `sources`

Массив источников:

```json
[
  {
    "file": "09_26.txt",
    "title": "Название материала",
    "url": "https://example.com/video"
  }
]
```

`file` — имя расшифровки. `title` и `url` необязательны и заполняются при наличии соответствующих данных.

#### `sections`

Массив идентификаторов разделов, например:

```json
[
  "foundation-soils",
  "thermal-insulation"
]
```

Раздел отвечает на вопрос, к какой большой тематической категории относится FAQ. Список допустимых разделов определяется в `data/sections.json`.

#### `tags`

Массив конкретных тематических меток, например:

```json
[
  "газобетон",
  "армопояс",
  "прочность-нагрузка"
]
```

Теги уточняют тему записи и используются для поиска и фильтрации. Словарь хранится отдельно в `data/tags.json`.

### `tags.json` — словарь тегов

Пример:

```json
{
  "version": 1,
  "updatedAt": "2026-10-09T00:00:00.000Z",
  "tags": [
    "армопояс",
    "газобетон",
    "мауэрлат",
    "прочность-нагрузка"
  ]
}
```

| Поле        | Тип               | Значение                         |
| ----------- | ----------------- | -------------------------------- |
| `version`   | number            | Версия структуры словаря         |
| `updatedAt` | string или `null` | Время последнего обновления      |
| `tags`      | string[]          | Список уникальных названий тегов |

Сейчас тег — это строка, а не объект. Дополнительные свойства вроде описания, приоритета или связи с проектом нельзя записывать в `tags.json`, пока формат данных специально не изменён.

Теги в FAQ должны соответствовать значениям словаря. При генерации тегов программа должна по возможности переиспользовать существующие формулировки, а при отсутствии подходящего варианта — добавлять новые.

Не следует без необходимости дублировать в тегах ID разделов: для этого уже существует поле `sections`.

### `sections.json` — справочник разделов

Пример структуры:

```json
{
  "version": 1,
  "updatedAt": null,
  "sections": [
    {
      "id": "foundation-soils",
      "name": "Фундамент и грунты",
      "description": "Основания, грунты и фундаменты"
    }
  ]
}
```

| Поле                     | Тип                   | Значение                         |
| ------------------------ | --------------------- | -------------------------------- |
| `version`                | number                | Версия структуры справочника     |
| `updatedAt`              | string или `null`     | Время обновления                 |
| `sections`               | array                 | Список допустимых разделов       |
| `sections[].id`          | string                | Стабильный идентификатор раздела |
| `sections[].name`        | string                | Человекочитаемое название        |
| `sections[].description` | string, необязательно | Описание области раздела         |

Идентификаторы разделов используются в данных FAQ. Не меняй их без обновления связанных записей и проверок.

### `processed.json` — история обработки

Пример:

```json
{
  "version": 1,
  "files": {
    "09_26.txt": {
      "hash": "sha256-хеш-содержимого",
      "processedAt": "2026-10-09T00:00:00.000Z",
      "itemCount": 50
    }
  }
}
```

| Поле                     | Тип    | Значение                    |
| ------------------------ | ------ | --------------------------- |
| `version`                | number | Версия структуры            |
| `files`                  | object | Обработанные исходные файлы |
| `files[имя].hash`        | string | Хеш содержимого расшифровки |
| `files[имя].processedAt` | string | Дата последней обработки    |
| `files[имя].itemCount`   | number | Количество извлечённых FAQ  |

Если хеш файла не изменился, обработка может быть пропущена. Изменение расшифровки позволяет программе определить, что её нужно обработать повторно.

## Статусы проверки

| Статус    | Значение                                    |
| --------- | ------------------------------------------- |
| `pending` | Запись ещё не прошла окончательную проверку |
| `review`  | Требуется ручная проверка                   |
| `ready`   | Запись признана готовой                     |

`reviewReasons` хранит причины проверки, например отсутствие подтверждающей цитаты, сомнительную формулировку или возможное противоречие с другой записью.

Статус `ready` сам по себе не доказывает фактическую достоверность ответа: качество источника и соответствие ответа расшифровке должны быть проверены.

## Резервное копирование

Команда:

```bash
npm run faq:backup
```

Создаёт копии доступных файлов данных. В зависимости от реализации `backup()` копии сохраняются рядом с оригиналами с суффиксом `.bak`.

Перед ручным редактированием JSON и любыми операциями очистки рекомендуется сделать резервную копию.

Не редактируй `processed.json` без понимания последствий: изменение или удаление записей может привести к повторной обработке расшифровок.

## Решение проблем

### FAQ есть, но тегов нет

Проверь словарь и запусти:

```bash
npm run faq:check-tags
npm run faq:retag
```

### Есть FAQ без подтверждающей цитаты

Получить список можно командой:

```bash
npm run faq:check-evidence
```

Отсутствующие цитаты следует восстанавливать из исходных расшифровок. Нельзя считать сгенерированную моделью цитату подтверждением, пока не проверено её присутствие в источнике.

### Изменения не применяются к расшифровке

Проверь `data/processed.json` и убедись, что файл действительно изменился. Если обработка пропускается по совпадающему хешу, повторно проверь алгоритм вычисления хеша и логику пропуска.

### Проверка сообщает о неизвестном теге или разделе

Сверь `sections` и `tags` в FAQ с соответствующими справочниками. Исправляй идентификаторы и назначения, а не отключай проверку.

### Ошибка JSON

Проверь запятые, кавычки и скобки в файле. JSON не поддерживает комментарии и завершающие запятые.

---

## Принципы работы с базой

1. Исходные расшифровки не заменяются данными FAQ.
2. Исходные формулировки и подтверждения нужно сохранять, когда они доступны.
3. Разделы и теги выполняют разные задачи.
4. Любое изменение данных должно сопровождаться проверкой.
5. Отсутствие ошибки структуры не гарантирует достоверность ответа.
6. Перед массовыми исправлениями нужно создавать резервную копию.
